# 05 位置合わせ（`src/fusion/align.ts`）

## 目的

NEAR と FAR の間の手ブレ・ピント移動に由来するズレを補正して、鮮鋭度の比較を正しくする。

## 方針

- **まず平行移動（dx, dy）のみ**を推定する。回転・スケールは今回は扱わない（将来拡張）。
- OpenCV は使わない。小さな解像度のグレースケール画像で、ブロックマッチングを行う。
- ぼけ方や明るさが2枚で異なるため、**輝度そのものではなく、勾配強度（エッジ）画像、または平均を引いて正規化した画像**で比較する。

## アルゴリズム

1. 入力：NEAR と FAR の `SkImage`。
2. 各画像を長辺 約256px に縮小し、グレースケールのピクセル配列（`Uint8Array` / `Float32Array`）を得る。
   - 縮小は Skia のオフスクリーンに描画して `readPixels` で読み出す（JPEGデコードを JS で行わない）。
3. 勾配強度（Sobel など）を計算する。
4. 粗密探索：
   - 長辺 64px 程度の縮小版で、±8px の全探索（SAD、または正規化相互相関）。
   - 次に 256px 版で、前段の結果の周りを ±2px で再探索。
   - 必要ならサブピクセル推定（放物線フィット）。
5. 推定したオフセットを、フル解像度の座標に換算して返す：`{ dx, dy }`（FAR を NEAR に重ねるための移動量）。
6. 信頼度を返す：最小コストと次点のコストの比、または相関値。**信頼度が低いとき**（背景が無地など）は、オフセットを `{0,0}` にフォールバックし、警告フラグを立てる。

## 適用

- ブレンドのシェーダーで、FAR をサンプリングする座標に `(dx, dy)` を加えて適用する。
- 範囲外になる端は、エッジクランプ。または、全体を共通の有効領域でクロップする（`FusionParams` で選択できると望ましい。既定はクロップなしのクランプ）。

## 性能目標

- 位置合わせ全体で **300ms 以内**（中級機）。超える場合は、探索範囲や解像度を縮小する。
- JSの重いループは、`Float32Array` とループ展開を意識して書く。

## 単体テスト（必須）

- 合成画像（ノイズ入りのテクスチャ）を、既知の `(dx, dy)` でずらし、`align` が誤差 ±1px 以内で復元できること。
- ずらし量 0 で 0 を返すこと。
- ガウスぼかしを片方に加えても推定が大きく外れないこと。
- 一様な画像で、信頼度が低いと判定されること。
- テスト用の画像配列はコード上で生成する（Skia に依存しない純粋関数部分でテストできるよう、「配列 → オフセット」の関数を分離する）。

## やらないこと

- 特徴点検出（ORB/SIFT）、RANSAC、ホモグラフィ
- 回転・スケール推定（フォーカスブリージングが目立つ場合の拡張案として `docs/DECISIONS.md` に記録するにとどめる）

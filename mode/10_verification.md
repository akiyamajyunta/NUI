# 10 検証（自動テスト・実機チェック・受け入れ基準）

## 自動チェック（AIが毎回実行する）

```bash
npx tsc --noEmit
npx eslint .          # テンプレートの設定に従う
npx jest              # 単体テスト（jest-expo）
```

エラーが残る状態で、マイルストーン完了としない。

## 単体テスト対象（純粋関数）

| 対象 | 内容 |
|---|---|
| `focusPoints.ts` | 正規化座標⇔ビュー座標の変換（縦向き・各種サイズ） |
| `align` の探索部 | 既知のずらし量の復元、ぼかし耐性、一様画像で低信頼 |
| `colorStats.ts` | 統計から補正係数、ゲインの上下限 |
| `stats.ts` | 最小／中央値／p90 |
| `focusVerify.ts` | 鮮鋭度スコア、OK/部分的/NG の判定 |
| マスク計算の CPU 参照実装 | シェーダーと同じ式を CPU で書き、数値の期待値を検証（任意） |
| `timeline.ts` | マークから区間時間を算出 |

テストの置き場所：対象ファイルと同じ階層の `__tests__/`。

## 画質の客観テスト（擬似ペア）

04 の擬似ペアで、`fuse` の結果と元画像のPSNR（または平均絶対誤差）を算出し、画面に表示する。目安として、ぼかしのみ・位置ズレなしで PSNR が十分高いこと（目標 30dB 以上。実測して `DECISIONS.md` に記録）。位置ズレ・明るさ差を加えたときの劣化も記録する。

## 実機チェックリスト（ユーザーが実施。AIは手順を提示する）

### カメラ
- [ ] 権限ダイアログが出て、許可するとプレビューが出る
- [ ] プレビューのタップ位置の物体にピントが来る（座標変換の確認）
- [ ] 被写体点と背景点で、実際にピントが移る（近い物と遠い物を置いて確認）
- [ ] シャッター押下で2枚が撮影され、連打できない
- [ ] 撮影時間が表示される

### 画像
- [ ] 撮影画像の向きが正しい（縦持ちで撮って縦向きに表示される）
- [ ] NEAR と FAR の向き・サイズが一致している

### 合成
- [ ] 擬似ペアで、結果が元画像に近い
- [ ] 実撮影で、ぬいぐるみと背景の両方がシャープ
- [ ] 輪郭に強い縁取り・二重像がない（あればパラメータで改善できる）
- [ ] デバッグ表示（マスク、鮮鋭度）が正しく見える
- [ ] 保存したJPEGがギャラリーで開ける

### 性能
- [ ] ベンチマークで 10回実行し、中央値・p90 を記録
- [ ] 合成の各工程の時間を記録
- [ ] 連続で5回撮影・合成してもクラッシュしない（メモリ）

## 受け入れ基準（最終）

| # | 基準 |
|---|---|
| A1 | `npx expo run:android` でビルドでき、実機で起動する |
| A2 | 07 の全画面が動作する |

| A6 | 合成時間の実測値が記録されている |
| A7 | tsc・lint・単体テストが通る |
| A8 | `docs/DECISIONS.md` に、決定・食い違い・実測が記録されている |

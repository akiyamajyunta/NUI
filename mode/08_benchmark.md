# 08 計測とピント検証

「1秒以内に撮れるか」を、感覚ではなく数値で判断するための機能。**この機能は、本アプリの中核であり、省略しない。**

## タイムライン計測（`src/perf/timeline.ts`）

- `performance.now()` を使い、`mark(label)` でマークを記録する。
- 撮影シーケンスで打つマーク（戦略により一部異なる）：

| ラベル | 意味 |
|---|---|
| `t0_press` | シャッター押下 |
| `focusA_start` / `focusA_end` | 被写体点へのフォーカス（行う場合） |
| `photoA_start` / `photoA_end` | 1枚目の撮影 |
| `focusB_start` / `focusB_end` | 背景点へのフォーカス |
| `delay_start` / `delay_end` | S3 の追加待ち |
| `photoB_start` / `photoB_end` | 2枚目の撮影 |
| `t_done` | シーケンス完了 |

- `totalMs = t_done − t0_press`
- 各区間の所要時間を算出し、画面に一覧表示できるようにする。
- 計測コード自体のオーバーヘッドを小さく保つ（ログ出力はシーケンス完了後にまとめて行う）。

## 統計（`src/perf/stats.ts`、純粋関数・単体テスト必須）

- 入力：数値の配列。出力：最小、最大、平均、中央値、p90。

## ベンチマーク画面（`app/benchmark.tsx`）

### 操作
1. 戦略（S1/S2/S3）と、解像度、S3 の待ち時間を選ぶ。
2. 被写体点と背景点を設定する（プレビューを表示）。
3. 「N回実行」（既定 N=10、間隔 1.5秒）を押す。
4. 結果を表を表示する。

### 表示項目
- 各回の `totalMs` と、区間ごとの時間。
- 統計（最小／中央値／p90／最大）。
- **判定：中央値が 1000ms 以内か**（✔/✘）。p90 も併記。
- 各回のピント検証結果（OK/NG）と、OK率。
- 合成の計測（任意）：直近の `FusionTimings`。

### 出力
- 結果を JSON でコピー（クリップボード）できる。端末情報（機種、OS、デバイス、フォーマット）を含める。
- JSON 形式：

```json
{
  "device": { "model": "...", "androidVersion": "...", "cameraDevice": "...", "format": "4000x3000" },
  "strategy": "S1",
  "runs": [ { "totalMs": 0, "segments": { "photoA": 0, "focusB": 0, "photoB": 0 }, "focusVerify": "OK" } ],
  "stats": { "min": 0, "median": 0, "p90": 0, "max": 0 }
}
```

## ピント検証（`src/perf/focusVerify.ts`）

`focus()` の Promise が解決しても、レンズが完全に静止する前に撮影されると、**ピントが合っていない写真**になる恐れがある。撮影後に、実際にピントが合っているかを画像から確認する。

### 方法
1. 撮影した2枚を作業解像度（長辺 約512px）に縮小し、グレースケール化する。
2. 各ピント点の周囲の矩形領域（例：画像の幅の 15%）で、ラプラシアン分散（または勾配エネルギー）を算出する。
3. 評価：
   - 被写体点の領域で `sharp(NEAR) > sharp(FAR) × k`
   - 背景点の領域で `sharp(FAR) > sharp(NEAR) × k`
   - `k` は既定 1.15（`constants.ts`）。
4. 両方満たせば OK、片方のみなら「部分的」、どちらも満たさなければ NG。
5. 位置ズレの影響を避けるため、検証は位置合わせ後（またはズレが小さい前提の簡易版）で行う。
6. 純粋関数部分（配列＋矩形 → 鮮鋭度スコア、判定ロジック）は単体テストを書く。

### 活用
- 撮影画面に、結果を小さく表示する。
- ベンチマークでは、NGが多い設定（S1で待ち時間なしなど）を、S3 の待ち時間で改善できるかを比較する材料にする。
- **速度とピント成功率のトレードオフ**が、このアプリの核心。レポートでは、「1000ms以内かつOK率 ≥ 90%」を満たす設定があるかを示す。

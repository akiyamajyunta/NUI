# 04 画像パイプライン（読み込み・向き・解像度・色合わせ・保存）

## 読み込み（`loadImage.ts`）

- 入力：`file://` URI。出力：`SkImage` と、元の幅・高さ。
- `Skia.Data.fromURI` と `Skia.Image.MakeImageFromEncoded` などを使う想定（**版により名前が違う。型定義で確認**）。
- 読み込みは非同期。呼び出し側がローディング表示を出せるよう、`onProgress` を受け取れる形にする。

## 向き（EXIF）補正（最重要の落とし穴）

- 縦持ちで撮影した写真は、ピクセルが横向きのまま EXIF で回転が指定されることがある。
- ライブラリが返す `orientation` 情報と、Skia が読み込み時に向きを適用するかどうかを、**実機で実測して確認**する。
- 適用されない場合は、`orientation.ts` で回転・反転を適用して「見た目どおりの向き」の `SkImage` にする。
- NEAR/FAR の2枚は同じ向きに揃える。向きの食い違いがあれば例外にする。
- ギャラリー画像（`expo-image-picker`）でも同様に確認する。

## 解像度方針

| 用途 | 解像度 |
|---|---|
| 位置合わせ | 長辺 約256〜320px のグレースケール |
| 鮮鋭度・マスク生成 | 作業解像度（長辺 既定1024px） |
| 最終ブレンド | 出力解像度（既定：入力のフル解像度） |

- フル解像度でテクスチャが作れない端末では、GPU の最大テクスチャサイズを確認し、超える場合は長辺を制限して縮小する（制限値は `constants.ts`、既定4096）。
- マスクは作業解像度で作り、**ブレンド時にバイリニア補間で拡大**する。
- 12MP の RGBA 画像は約48MB。同時に保持する大きな画像は最大でも3枚程度（NEAR、FAR、出力）に抑える。解析用の中間画像は作ったらすぐ解放する。

## 色合わせ（`colorStats.ts`）

ピント移動で露出・WBが変わる問題を補正する。

1. 作業解像度の画像から、チャンネルごとの平均と標準偏差を求める（位置合わせ後の重なり領域のみ）。
2. FAR をNEARに合わせるゲイン・オフセットを求める：
   `farAdjusted = (far - meanFar) * (stdNear / stdFar) + meanNear`
   ゲインには上下限（例 0.8〜1.25）を設ける（極端な補正を防ぐ）。
3. シェーダーのユニフォームとして渡し、ブレンド時に適用する。
4. `FusionParams.colorMatch` で切り替え可能にする。
5. 注意：2枚で被写体領域が異なるため、全体統計の補正は完全でない。まずはこの簡易版で実装し、明るさ差が目立つ場合の改善案を `docs/DECISIONS.md` に記録する（例：マスク境界付近のみで統計をとる）。
6. 純粋関数部分（統計から補正係数を出す）は単体テストを書く。

## 保存（`saveImage.ts`）

- 結果の `SkImage` を JPEG（品質 90〜95）にエンコードし、キャッシュに書き出す。
- `expo-media-library` で、端末のギャラリーに保存する。専用アルバム（例：「ぬいぐるみ合成」）に入れる。
- 保存権限は、Android のバージョンによって必要な権限が違う。`expo-media-library` の説明に従う。権限が拒否されたら、キャッシュの共有（Share）にフォールバックするか、エラーを表示する。
- エンコードは重い。UIスレッドを長時間ブロックしないよう、進捗表示を出す。

## 擬似ペア生成（`syntheticPair.ts`、テスト用）

カメラがなくても合成の品質を検証できるよう、1枚の鮮明な写真から NEAR/FAR の擬似ペアを作る。

1. 元画像 `I`（鮮明）を用意する。
2. 既知のマスク `M_true`（例：画像中央の楕円を「手前」とする）を作る。
3. `NEAR = M_true の内側はI、外側はIをぼかしたもの`、`FAR = 内側はIをぼかしたもの、外側はI`。
4. 任意で、FARに微小な平行移動（例 dx=7, dy=-4）と明るさ変化（例 ×0.9）を加える。
5. `fuse(NEAR, FAR)` の結果を `I` と比較する（PSNR など）。位置合わせ・色合わせ・マスクが正しく働くかの客観的なテストになる。

ホーム画面から、元画像を1枚選んで擬似ペアを作り、そのまま合成まで流せるデバッグ機能を用意する。

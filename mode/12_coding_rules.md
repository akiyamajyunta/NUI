# 12 コーディング規約・禁止事項

## 言語・設定
- TypeScript、`strict: true`。`any` を使わない（やむを得ない場合は理由をコメント）。
- React は関数コンポーネントと Hooks。クラスコンポーネントは使わない。
- コメントは日本語、識別子は英語。「なぜそうするか」を書き、「何をしているか」の言い換えは避ける。

## 構成
- 1ファイル 300行程度を目安に。超えるなら分割する。
- 画面（`app/`）にロジックを書かない。フックとサービスに出す。
- 純粋関数と副作用を分離する（02）。
- マジックナンバーは `constants.ts` に。単位（ms、px、正規化）を名前かコメントで明示する。

## 非同期とパフォーマンス
- UIスレッドを長くブロックしない。重いループは、小さな画像で行うか、分割する。
- 配列は `Float32Array` / `Uint8Array` を使う。ホットパスで、配列のmap・filter・スプレッドを避ける。
- 大きな `SkImage` は、使い終わったら参照を手放す。
- `useEffect` のクリーンアップで、タイマー・購読・処理の無効化を行う。
- 再レンダリングを抑える（`useMemo`、`useCallback` は計測してから）。

## 依存関係
- 02 の表に無い依存を追加するときは、`docs/DECISIONS.md` に理由を書く。
- 非推奨APIを使わない。警告が出たら対処する。
- **使用禁止**：OpenCV 系、TensorFlow 系、外部APIクライアント、アナリティクス/クラッシュ報告SDK、広告SDK。
- **ネットワークアクセスを行うコードを書かない**。

## ライブラリAPIの扱い
- 版を確認し、型定義（`node_modules`）を読んでから書く。
- 不確かなAPIを使うときは、まず最小の動作確認コードで検証してから本実装に組み込む。

## ログ
- `console.log('[tag] message', data)` 形式。画像データ・URIのフルパス・個人情報を出さない（URI は末尾のみ）。
- 本番ビルドで過剰なログを出さないよう、`__DEV__` で切り替えるラッパー `log.ts` を用意する。

## UI
- すべてのユーザー向け文言を、`src/ui/strings.ts`（または各画面の先頭）にまとめる。将来の多言語化の余地を残す。
- アクセシビリティ：`accessibilityLabel` を主要ボタンに付ける。

## テスト
- 純粋関数は単体テストを書く。テストは決定的に（乱数はシード固定）。
- テストのために、本実装の設計を歪めない。

## Git（リポジトリがある場合）
- マイルストーンごとにコミット。メッセージは `M3: add fusion MVP` のように。
- `android/` と `ios/` は、prebuild の生成物。`.gitignore` の扱いは、テンプレートの設定に従う。

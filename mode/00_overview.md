# 00 概要・要件

## 背景の課題

ぬいぐるみと背景を1枚の写真に収めるとき、ぬいぐるみにピントを合わせると背景がボケ、背景に合わせるとぬいぐるみがボケる。スマホのカメラは被写界深度が浅く、1枚では両方にピントを合わせにくい。

## 解決方針

1. ぬいぐるみにピントを合わせた1枚（**近景画像 NEAR**）と、背景にピントを合わせた1枚（**遠景画像 FAR**）を、ボタン1回で連続撮影する。
2. 2枚を位置合わせし、各ピクセルで「よりシャープな方」を選ぶマスクを作って合成する（フォーカススタッキングの2枚版）。
3. すべて端末内で完結させる。

## 必須要件

| # | 要件 |
|---|---|
| R1 | スマホアプリとして実装する（Android を主対象） |
| R2 | 外部APIを使わない。ネットワーク通信を行わない |
| R3 | ミドルレンジ帯のAndroid端末で実用速度で動く（目安：Snapdragon 6/7系、RAM 4〜8GB） |
| R4 | React Native（Expo）で実装する。言語は TypeScript |
| R5 | 開発は **Development Build（expo-dev-client）のローカルビルド** で行う。Expo Go は使わない |
| R6 | **ボタン1回で、2枚の撮影を1秒以内に完了する**（合成処理の時間は含めない） |

## 成功条件

- 撮影シーケンス（ボタン押下から2枚目の撮影完了まで）が、検証端末で **中央値1000ms以内**。達成できない場合は、実測値と、短縮できなかった要因を `docs/DECISIONS.md` に記録する。
- 合成結果で、ぬいぐるみと背景の両方が目視でシャープである。
- 合成処理（読み込み〜結果表示）が、出力 1200万画素級で **数秒以内**（目標 3 秒、許容 5 秒）。プレビュー用の低解像度合成は 500ms 以内を目標にする。

## スコープ

### やること
- 2点フォーカス連続撮影、位置合わせ（平行移動）、鮮鋭度ベース合成、色合わせ、結果の保存
- 計測機能（撮影時間・処理時間・ピント検証）
- ギャラリーの2枚から合成するモード
- 合成パラメータの調整UIとデバッグ表示

### やらないこと
- iOS 対応（コードが動いても検証しない）
- OpenCV、TensorFlow、ML モデル、クラウド処理
- 3枚以上のスタッキング（将来拡張として設計だけ妨げない）
- 動画、ライブ合成プレビュー（撮影前の合成プレビュー）
- アカウント、課金、広告、アナリティクス

## 用語

| 用語 | 意味 |
|---|---|
| NEAR / 近景画像 | ぬいぐるみ（手前の被写体）にピントが合った画像 |
| FAR / 遠景画像 | 背景にピントが合った画像 |
| 被写体点 | ユーザーが指定した、ぬいぐるみ上のピント位置（正規化座標 0〜1） |
| 背景点 | ユーザーが指定した、背景上のピント位置（正規化座標 0〜1） |
| 鮮鋭度マップ | 各ピクセルのシャープさを表す値（ラプラシアン応答の局所エネルギー） |
| マスク | 0 = FAR を採用、1 = NEAR を採用 とするブレンド係数マップ |
| 撮影シーケンス | ボタン押下から2枚目の撮影完了まで |
| 作業解像度 | 解析（鮮鋭度・位置合わせ）に使う縮小解像度（長辺 約1024px） |
| 出力解像度 | 最終合成画像の解像度（既定：撮影解像度のまま） |

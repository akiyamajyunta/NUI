# 03 カメラと撮影（2点フォーカス連続撮影）

最重要・最難関のファイル。**ボタン1回・1秒以内**を実現できるかは、ここと `08_benchmark.md` の計測で決まる。

## 基本方針

- カメラは `react-native-vision-camera` を使う。**APIは記憶で書かず、インストール版のドキュメントと型定義で確認する。**
- 使う想定のAPI（版により名前・シグネチャが違う可能性あり。必ず確認）：
  - `useCameraDevice` / `useCameraFormat` / `useCameraPermission`
  - `<Camera photo ... />`
  - `camera.focus(point)`（指定点でのAF。Promise が何を待つかを実測で確認）
  - `camera.takePhoto({...})`（シャッター音オフ、速度優先のオプション）
  - `camera.takeSnapshot(...)`（低解像度・高速。戦略S2用）
- フレームプロセッサは使わない。

## デバイスとフォーマットの選択

1. 背面カメラを使う。
2. **単一レンズを選ぶ**：マルチカメラ（論理カメラ）だと、ピント移動時にレンズが切り替わり画角が変わる恐れがある。広角（wide-angle）の単一物理レンズを優先して選び、選んだデバイス情報（`supportsFocus` など）をログに出す。
3. `supportsFocus` が false の場合は、エラー画面を出して撮影機能を無効にする（09参照）。ただしギャラリー合成モードは使える。
4. フォーマットは「速度優先」で選ぶ：
   - 既定の目標：写真解像度 約800万〜1200万画素（例 4000×3000 以下）。
   - ミドルレンジ機では高解像度ほど `takePhoto` が遅い。**解像度は設定で切り替えられるようにし**、ベンチマークで比較する。
   - プレビューfps は30で十分。
5. HDR、夜景モード、ビデオ安定化などの重い処理は **オフ**にする（利用可能なプロパティのみ）。
6. フラッシュは常にオフ。シャッター音は、法規上許される範囲でオフにする設定を用意（既定はユーザー設定。日本国内の端末でシステム側が強制する場合があるため、効かなくても警告しない）。

## ピント点の指定

- ユーザーは、プレビュー上をタップして **被写体点** と **背景点** を設定する（07参照）。
- 内部では `NormalizedPoint`（0〜1）で保持し、`focus()` に渡す直前にビュー座標へ変換する（`focusPoints.ts`、純粋関数、単体テストあり）。
- 縦持ちのプレビューと、センサー座標の違いに注意する。**座標変換が正しいかを、実機で「タップ位置の物体にピントが来る」ことで確認する**（10の実機チェック）。

## 撮影シーケンス

`captureSequence(strategy, points, camera)` は次を行う。

1. `t0` を記録（ボタン押下）。
2. 戦略を実行して `near` と `far` を得る。
3. 各ステップで `timeline` にマークを打つ（08参照）。
4. 最後に **次回に備えて被写体点にピントを戻す**（これは `totalMs` に含めない。結果表示の裏で実行）。
5. `CaptureResult` を返す。

連打を防ぐ：シーケンス実行中は、シャッターボタンを無効にする。

## 撮影戦略（差し替え可能にする）

```ts
export interface CaptureStrategy {
  id: string;
  label: string;
  run(ctx: {
    camera: CameraRef;           // vision-camera の Camera ref
    nearPoint: NormalizedPoint;
    farPoint: NormalizedPoint;
    mark: (label: string) => void; // タイムラインにマーク
    settings: CaptureSettings;
  }): Promise<{ near: PhotoLike; far: PhotoLike }>;
}
```

実装する戦略：

| ID | 内容 |
|---|---|
| **S1 sequentialFocus** | 被写体点にピントが来ている前提で `takePhoto` → `focus(背景点)` を await → `takePhoto`。速度優先オプション。 |
| **S2 snapshotFocus** | S1 と同じ手順だが `takeSnapshot` を使う（低解像度・高速）。画質は落ちる前提で、速度の下限を知るために実装。 |
| **S3 fixedDelay** | `focus(背景点)` の await に加えて、固定の追加待ち時間（0/50/100/200ms を設定可）を入れる。Promise 解決がレンズの安定より早い場合の対策。 |

- どの戦略でも、**1枚目の前に被写体点へフォーカスし直すかどうか**を設定で切り替える。既定は「プレビュー中に被写体点に合わせ済みなので、再フォーカスしない」（1枚目撮影時の遅延を避けるため）。ただし直前に背景点へ動かした場合は再フォーカスが必要。`currentFocusTarget` を状態として管理する。
- 将来、他の戦略（レンズ位置の直接指定など、ネイティブモジュールが必要なもの）を足せる構造にする。**今回はネイティブモジュールの自作はしない**（`docs/DECISIONS.md` に「手動レンズ位置が必要ならネイティブモジュール化を検討」と記録するにとどめる）。

## 露出・ホワイトバランスの扱い

- ピント点を変えると、測光点も変わり、2枚の明るさが違うことがある。
- ロック機能がAPIにあれば使う。なければ、**合成側の色合わせ（04）で補正する**ことで対処する。
- ロックの有無・効果は `docs/DECISIONS.md` に記録する。

## 手ブレ・位置ズレ

- 撮影間隔は約1秒以下のため、手持ちでも小さなズレが出る。位置合わせは05で行う。
- 撮影中に「動かさないでください」の表示を出す（ボタン押下から結果が出るまで）。

## 出力

- `CapturedPhoto` に、`uri`（`file://` 付き）、実寸の `width/height`、向き情報、ピント点、役割（NEAR/FAR）を入れて返す。
- 写真ファイルは、アプリのキャッシュディレクトリに置かれる。合成終了後、不要になった一時ファイルは削除する（ただし「元画像を保存」オプションがオンのときは保存）。

## やらないこと

- ネイティブコード（Kotlin/Swift）の追加
- フレームプロセッサ、フレームごとの解析
- 顔検出・被写体検出による自動ピント点設定（手動指定のみ）
